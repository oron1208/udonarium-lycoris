GUIDE

🚀 自分のサーバーへの設置ガイド

ユドナリウムリコリスを自分のサーバー（自宅PC・VPS）で動かす方法を、バックエンド（通信方式）の基礎から解説します。

01

はじめに：何ができる？

ユドナリウムリコリスは公式サーバーで誰でも使えますが、自分のサーバーで動かす（セルフホスト）ことにもメリットがあります。

  • 🕐部屋のデータが自分の手元に残る（公式サーバーは24時間で自動削除）
  • 🔒セッション内容を自分だけで管理できる（プライベートな卓）
  • ⚡仲間内だけの専用サーバーとして常時運用できる
  • 📚音楽ライブラリや画像を好きなだけ置ける

面倒なことはしたくない場合は、公式サーバー（https://udonarium-lycoris.ddns.net/）の利用がおすすめです。セルフホストは「常時使いたい」「データを自分で管理したい」人向けです。

02

仕組みを知ろう

リコリスの通信は、大きく分けて 3つの部品 で成り立っています。

🌐 プレイヤーのブラウザ卓の画面そのもの（distフォルダの中身）
⇅ 接続
🖥️ unified-server（あなたのサーバー）画面の配信 ＋ 部屋データの保存 ＋ プレイヤー同士の仲介
⇅ 方式によって利用
☁️ SkyWay（NTTコミュニケーションズのサービス）プレイヤー同士を直接つなぐ「仲介役」。使わない方式もあります

ポイントは、unified-server 1本ですべてが完結すること。Webページの配信、部屋データの保存、プレイヤー同士のメッセージ中継、そしてSkyWayの認証トークンの発行まで、この1つのプログラムが全部やってくれます。あなたはこれを起動するだけです。

では「SkyWayって何？なぜ選べるようになっているの？」という話を見ていきましょう。

03

3つの通信モード

リコリスは、プレイヤー同士が「どうやって会話（データ）をやり取りするか」を3つの方式から選べます。設定は dist/udonarium-lycoris/assets/config.yaml の mode: 1行で切り替えます。

🔶 websocket-relay（リレー方式）— 登録不要でいちばん簡単

プレイヤー間のすべての通信を、あなたのサーバーが中継します。SkyWayなどの外部サービスに登録する必要はありません。サーバーを立てたら、それだけで動きます。

「relay（リレー）」＝駅伝の「中継」。全員のメッセージをサーバーが受け取って、全員に配るイメージです。

🔶 websocket-signaling（P2P方式）— サーバーは呼び出し役だけ

サーバーは「誰がどこにいるか」の連絡（シグナリング）だけを担当し、実際のゲームデータはプレイヤー同士が直接やり取りします。サーバーの負荷は最も軽いですが、通信環境によってはプレイヤー同士が直接つながれず、接続に失敗することがあります。

🔶 skyway2023（SkyWay方式）— インターネット越しの本命

NTTコミュニケーションズが提供するWebRTCサービス「SkyWay」を利用する方式です。SkyWayがプレイヤー同士の直接接続を確立してくれるので、インターネット越しでも安定して通信できます。公式サーバーもこの方式で動いています。

⚠️

SkyWayを使うには無料のアカウント登録と、サーバーへの「アプリケーションID・シークレットキー」の設定が必要です。ここがつまずきやすいポイントですが、このガイドの手順07で順番に解説します。

比較表

websocket-relaywebsocket-signalingskyway2023
追加の登録不要不要SkyWayアカウント（無料）
設定の手間ほぼゼロ少ないややある
インターネット越し◎ 安定△ 環境により不可◎ 快適
サーバーの通信量多め（中継するため）少ない少ない
向いている場面初めて／LAN内／小規模上級者常用・公開サーバー
04

どれを選べばいい？

迷ったら、次の順番で考えればOKです。

  • 🏠まず動かしてみたい（自宅のPC、家族・同じWi-Fi内で遊ぶ）
    → websocket-relay。このあとの手順05で5分で起動できます。
  • 🌍遠くの友達とインターネット越しに遊びたい
    → まずは websocket-relay でも動きます（サーバーの回線が通信量を引き受けます）。卓の規模が大きくなってきたら skyway2023 へ切り替えましょう。
  • 🏛️常時公開のサーバーを運用したい
    → skyway2023 推奨。サーバー負荷が軽く、接続も安定します。

設定は config.yaml の1行を書き換えるだけ。後からいつでも切り替えられます。まずは relay で始めて、必要になったら SkyWay に乗り換えるのがおすすめです。

05

かんたん設置（ZIPで起動）

必要なファイルすべて入り のパッケージを用意しています。ダウンロードして、手順どおりに進めるだけです。

📦

📥 セルフホストパッケージのダウンロード
udonarium-lycoris-v1.91-selfhost.zip（約12MB）
内容：ブラウザアプリ（dist）・サーバー本体・Dockerfile・導入手順書（SETUP.md）

前提：Node.js のインストール

サーバーを動かすPCに Node.js（22以上を推奨）が入っていなければ、公式サイトからインストールしておきます。

手順1：展開と依存のインストール

ZIPを展開し、そのフォルダでターミナル（WindowsならPowerShell）を開いて実行します。

npm install --omit=dev --no-save lzbase62@^2.0.0 archiver@^5.3.0
cd signaling-server
npm ci --omit=dev
cd ..

手順2：通信モードを relay に変更

dist/udonarium-lycoris/assets/config.yaml をテキストエディタで開き、mode: の行を書き換えます。

backend:
  mode: websocket-relay   # skyway2023 → websocket-relay に変更

手順3：起動

node unified-server.js

「Udonarium Lycoris self-hosted server」と表示されれば起動完了です。停止は Ctrl+C。

手順4：アクセス

プレイヤー全員がブラウザで https://<サーバーのIP>:12081/ を開きます。サーバーと同じPCなら https://localhost:12081/。

🔒

証明書の警告について：リコリスは初回起動時に自動で自己署名証明書を作ります。そのため初回アクセス時に「安全ではありません」という警告が出ますが、これは自分用の証明書だから正常な挙動です。Chromeなら「詳細設定」→「…にアクセスする」で先へ進めます。

仲間のPCからアクセスするには、サーバーPCのIPアドレスが必要です（Windowsなら ipconfig、Linux/macOS なら ip addr / ifconfig で確認。192.168.x.x のような値です）。ファイアウォールでポート 12081 を許可してください。

更新・データについて

  • 💾部屋データ・画像・音声はすべて data/ フォルダに保存されます。バックアップはこのフォルダだけでOK
  • ⬆️バージョンアップは新しいZIPを同じ場所に展開し、data/ を残したまま再起動するだけ
06

Docker で設置

Dockerを使える環境なら、コマンド2つで起動できます。パッケージZIPに Dockerfile を同梱しています。

docker build -t udonarium-lycoris .

docker run -d --name udonarium-lycoris \
  -p 12081:12081 \
  -v udonarium-data:/app/data \
  udonarium-lycoris

SkyWayを使う場合は、.env ファイルを作成してから --env-file .env を docker run に追加します（内容は手順07参照）。データは udonarium-data ボリュームに永続化されます。

07

SkyWay を使って公開する

インターネット越しに安定して遊びたい場合は、SkyWay方式（skyway2023）がおすすめです。「Webサーバーを置いただけでは動かない」と言われる原因の多くが、この設定です。順番にやっていけば大丈夫。

Step 1：SkyWay のアカウント登録

SkyWay公式サイトで無料のアカウントを作成します。開発者登録後、ダッシュボードから新しいアプリケーションを作成してください。

Step 2：キーの取得

作成したアプリケーションの詳細画面に、次の2つが表示されます。

  • 🔑アプリケーションID — 公開してよいID
  • 🗝️シークレットキー — 絶対に他人に見せてはいけないキー

Step 3：サーバーに設定

サーバーを起動するフォルダに .env という名前のファイルを作り、次の2行を書きます。

SKYWAY_APP_ID=ここにアプリケーションID
SKYWAY_SECRET_KEY=ここにシークレットキー

このキーはサーバーだけが使います。リコリスのサーバーは、このキーでプレイヤー1人1人に「入室許可証（トークン）」を発行する仕組みです。だからこそ「SkyWayの認証トークンを発行するサーバが必要」というエラー表示になるのです。

Step 4：通信モードの確認

dist/udonarium-lycoris/assets/config.yaml の mode: を skyway2023 にします（初期状態でそうなっています）。変更していた場合は戻してください。

Step 5：動作確認

サーバーを起動し、次のコマンドでトークンが発行されれば成功です。

curl -k -X POST https://localhost:12081/v1/skyway2023/token \
  -H "Content-Type: application/json" \
  -d '{"formatVersion":1,"channelName":"test","peerId":"test"}'

{"token":"eyJhbGciOi…"} のような長い文字列が返ってくればOK。エラーが出る場合は .env のスペルやファイルの位置（unified-server.js と同じフォルダ）を確認してください。

SkyWayの管理画面でも、アクセスを許可するドメインやIPの設定が必要です。SkyWayのドキュメント「認証・ドメイン設定」をご確認ください。

08

ソースからビルドする（開発者向け）

自分でカスタマイズしたい場合は、GitHubからソースを取得してビルドできます。ビルドには Node.js 16系（Angular 13を使用のため）が無難です。

git clone https://github.com/oron1208/udonarium-lycoris.git
cd udonarium-lycoris
npm install
npx ng build --configuration production

ビルド成果物は dist/udonarium-lycoris/ に出力されます。このフォルダを、パッケージZIPの dist/udonarium-lycoris/ と入れ替えれば手順05と同じように起動できます。

💡

送受信まわりのカスタマイズは src/app/class/core/system/network/ 配下、サーバー本体は unified-server.js にあります。改善やバグ報告は GitHub の Issue・Pull Request で歓迎します。

09

トラブルシューティング

症状原因対処
「APIバックエンド＜URL＞にアクセスできませんでした。SkyWayの認証トークンを発行するサーバが必要です」 モードが skyway2023 なのに、SkyWayのキー設定がされていない 手順07の .env 設定を行う。または mode: を websocket-relay に変更
自分は入室できるが、他の人が部屋に入れない・相手の卓が見えない ポート12081が開いていない／IPが違う ファイアウォールで12081を許可。アクセスURLのIPを再確認（サーバーPCのIP）
「安全ではありません」という警告が出て進めない 自己署名証明書による正常な警告 「詳細設定」→「…にアクセスする」で進める。常用するなら正式な証明書（Let's Encrypt等）を取得
置いた画像・音声が消える data/ フォルダの削除・サーバー再構成 data/ は消さずに保管。Dockerなら -v でボリュームマウントする
新しいバージョンに更新したら画面が古いまま ブラウザのキャッシュ Ctrl＋Shift＋R で強制再読み込み
10

用語ミニ集

  • 📡シグナリング（signaling） — 通信を始める前の「名寄せ」。誰がどのアドレスにいるかを教え合う事務連絡のこと
  • 🤝P2P（ピアツーピア） — サーバーを経由せず、プレイヤー同士が直接データをやり取りする方式。速いが、環境によっては直接つながらない
  • 🌉TURN — 直接つながらない環境のために、指定のサーバーを経由させて通信を成立させる仕組み。SkyWayはこれを自動提供
  • 🔐HTTPS（セキュアコンテキスト） — 暗号化された通信。SkyWay（WebRTC）を使うには必須のため、リコリスはhttpsで起動します
  • 🎟️トークン — SkyWayへの「入室許可証」。サーバーがシークレットキーで署名して発行するため、キーをブラウザ側に置かずに済みます

わからないことがあれば、GitHubの Issue やコミュニティで気軽にどうぞ。
