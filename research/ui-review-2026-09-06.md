# UI/UX点検（2026-09-06）

## 範囲・制約
現行ワーキングツリーのメニュー、接続、ロビー、部屋作成、画像取り込み、オプション、チャット、ホットバー、共通パネルを点検。実装・配信変更なし。既存の通信・画像・照明変更は保持。
ブラウザで https://localhost:12081 を開いたが ERR_CONNECTION_REFUSED。今回の判断はソース確認であり、実画面の重なり・コントラスト・スマホ操作・複数人挙動を実証したものではない。全機能の動作保証ではない。

## 優先度A：先に改善

1. **取り込み経路で画質の扱いが違う（実装確認）**
   - `src/app/class/core/file-storage/file-archiver.ts` handleImage は直接取り込み時に2MiB超を自動圧縮。ZIPは選択式。
   - `src/app/component/file-storage/file-storage.component.html` は「１ファイルにつき2MBまで」と案内し、自動圧縮を説明していない。
   - 提案：通常画像にも同じ選択画面を使い、原画保持を初期値にする。MB/MiBを統一。取り込み結果に容量・寸法・圧縮有無を表示。
   - 受入：同じ画像を直接/ZIPから原画保持で入れると同じバイト列になり、表示説明も一致。

2. **接続状態が判断しづらい（表示構造確認）**
   - peer-menu は接続相手ごとの時刻を表示、server-status はサーバー統計を「接続人数」と表示、network-indicator は sync のみ。
   - 提案：「この部屋の参加者」「自分と同期できている相手」「サーバー全体」を分離。接続中・正常・再接続中・失敗を文字で示し、最終更新と復旧案内を表示。
   - 注意：人数を同じ既存配列から二重表示せず、部屋メンバー情報と実データ接続の独立した状態を使う。自分を含むか明記。

3. **ルーム作成のパスワードが平文表示（実装確認）**
   - room-setting.component.html の password 入力は type 未指定。接続画面では伏せ字/表示切替あり。
   - 提案：作成画面も password 型＋明示的な表示切替に統一。画面共有時の見え方を改善。通信暗号化の不具合を指摘するものではない。

4. **退室・部屋移動が再読み込み頼み（案内確認）**
   - lobby/room-setting は他参加者と接続中ならページリロードで切断するよう案内。
   - 提案：「退室してロビーへ」を設け、未保存データの扱いと必要な保存手順を案内。サーバー復帰可能期間と手元ZIP保存を区別。
   - 受入：後片付け・再入室まで確認し、他参加者の部屋を削除しない。

## 優先度B：小さく直せる不整合

5. **同じ設定が違う名前で重複（実装確認）**
   - options-panel.component.html の「アクティブパネルを手前に表示」「パネルを最前面に表示」はどちらも isActivePanelForeground / toggleActivePanelForeground。
   - 提案：一項目に統合し、「クリックしたウィンドウを手前にする」と動作に合わせる。

6. **設定の影響範囲が分からない（説明不足）**
   - options-panel.component.ts の多数の表示設定は localStorage。画面には「全員の立ち絵…」など全員への設定変更とも読める文言。
   - 提案：「自分の画面のみ」「部屋全体」「GM操作」を各設定に明記。各設定の実際の保存先/同期範囲は個別確認して分類する。

7. **略語・内部用語・状態表現が混在（表示確認）**
   - CS、VN、自動Fit、rotate + 90、Heap/Load、ADVANCED、「照明視覚中」「オプション中」、ON/OFFと畳む/展開が混在。
   - 提案：「カーソル共有」「会話演出（VN）」「立ち絵の高さを合わせる」「照明・視界」に統一。内部数値は詳細へ。ボタンが現在状態か実行動作か統一。

8. **アイコン操作の名前/キーボード導線（実装確認）**
   - ui-panel.component.html の最小化/最大化/閉じるボタンは説明ラベルなし。macro-hotbar のピンはクリックするdiv。
   - 提案：button化、日本語aria-label、フォーカス表示、トグルのaria-pressed。ツールチップだけに頼らない。

9. **ホットバーの初期操作が特殊（導線改善案）**
   - 自キャラ設定が「Altキーで対象にしたコマ」を前提にし、マクロ編集は右クリック経路を持つ。
   - 提案：自キャラを一覧から選択可能にし、空スロットに「マクロを登録」、編集ボタンを明示。既存の熟練者向け操作は残す。

10. **破壊操作と配置リセットが隣接（表示確認）**
    - options-panel で視点/位置リセットとホットバー全クリアが同じ行。全クリアには既に確認あり（確認がないとは指摘しない）。
    - 提案：全削除を管理欄に分離し、復元/エクスポート導線を付ける。

11. **読込・保存対象のラベルが曖昧（表示確認）**
    - data-import-menu の「ZIP読込」はXMLも受け付ける。メインメニューは「保存」のみ、ホットバーにも「保存」がある。
    - 提案：「卓・コマデータを読み込む（ZIP/XML）」「卓データをZIP保存」「ホットバー設定を保存」と対象と保存先を明記。

## 実画面で追加検証する候補（不具合確定ではない）
- 1366×768、ブラウザ125/150%、狭幅でチャットの固定em幅セレクターとホットバー編集領域がはみ出さないか。
- 複数パネル、VN、照明、ホットバー同時表示時の重なり・クリック阻害。
- チャット送信者/宛先が一目で区別できるか。個別送信には既存direct-messageクラスがあり、強調不足は実画面で評価する。
- ダーク背景の注意書き・ボタンのコントラスト、Tab順序、タッチ操作。
- 通信切断/復旧時の表示と実同期の一致、空部屋復帰と保存説明の一致。

## 推奨実施順
Aの画質選択統一・接続状態・パスワード表示を先行。次に重複/用語/影響範囲を整理。その後、退室導線、ホットバー導入、レスポンシブ実画面検証。大規模レイアウト刷新は利用中の操作を崩すため最後に検討。
