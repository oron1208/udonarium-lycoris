# Unityダイスが部屋反映ループで見えなくなる問題（2026-11-11）

## 調査結果

専用LAN Relay試用でダイス更新そのものは保存されていた。保存済みの大きい部屋から、ZIP読み込み等でオブジェクトとチャットタブを入れ替えた場合に発生する。

1. サーバーの部分同期対策は前回保存の件数を下限にしていた。明示的なDELETE履歴があっても、小さい新しい部屋を部分同期と誤認してsnapshot-rejectedを返す。
2. ブラウザは拒否されると古いsnapshotの強制取得/反映を行う。snapshot中にない現在のチャットタブはローカル整合処理で除去される。
3. 強制反映でも以前の高いlastSeqを維持したため、snapshot以降の履歴をスキップしていた。加えてサーバーは同じ送信者自身の履歴を除外していた。
4. その結果、新タブとUnityダイスが見えなくなる一方、再び保存拒否となり、部屋データ反映表示が繰り返される。

旧版の隔離再現では、Unityダイスが一度届いた後、拒否2回・強制反映2回で新タブと結果が見えなくなった。利用者の部屋を検証用に書き換えてはいない。

## 修正

- `unified-server.js`: 保存済みsnapshotと順序付きUPDATE/DELETE履歴から、存在すべきオブジェクト集合を投影し、その件数を保護基準に使う。削除はクライアントの小さい配列から推測せず、履歴上の明示削除と子の削除に限る。GZip/MessagePackを処理し、投影できない場合は従来の保守的な基準を維持する。
- タブ/タブ一覧/チャットが最新履歴より不足・古い候補は拒否し、復旧に必要なタブと結果を保存時に履歴圧縮で落とさない。
- 先頭からの復元には、要求者自身が送ったsnapshot後の履歴も含める。途中からの通常差分再開は従来どおり自身の既反映更新を除く。
- ブラウザの強制snapshot反映ではlastSeqをsnapshotSeqへ戻してから後続履歴を再生する。
- サーバーが使用する`msgpack-lite@0.1.26`をDockerの実行時依存にも明示した。root package.jsonには既存依存として存在する。

サーバー権限モデルやトランザクションを導入した修正ではない。既存のtrusted room peerと版番号の意味は変更しない。キャッシュした投影はroom.seqが変わると再計算し、保存JSONには含めない。

## 検証

- `node tools/test-relay-snapshot-guard.cjs`: 初回保存・根拠のない縮小拒否・空保存拒否・GZipの再帰削除による正当縮小・自身の変更の完全復元・不足した新ダイス/新タブの圧縮防止・保存後再入室、8項目。
- 隣接`../lycoris-unity/Tools/verify-dice-resync.cjs`: 旧版と修正版の比較。固定IDではなく固有隔離部屋の新規ブラウザ・実Windows Unity0.2.2を使う。`FIXED=1 node ../lycoris-unity/Tools/verify-dice-resync.cjs`で修正版を検証。
- 入れ替え後のタブへダイス着信、実チャットDOMの描画、古いsnapshot強制復元、12回連続ロールで反映ループ増加0、Native再接続、後から参加するブラウザで履歴と実表示を確認する。
- productionビルドの新規起動で盤面・例外0・Angular開発APIなし・WebGL初期化0を確認する。

証跡は`tmp/unity-dice-sync/`と隣接Unityの`Evidence/dice-resync-{before,after}.json`。個人のチャット本文や部屋のコピーは公開ソースへ含めない。

## 配信先

専用試用 `http://192.168.2.54:14581/` のみ反映。ブラウザ参加者はページを再読み込みして同じ部屋へ入り直す。Unity本体は0.2.2のままでよい。
旧サーバーはSIGTERMで保存をflushして停止し、部屋JSON・設定・旧index/サーバーをUserData/compat-backupsへ退避した。画像/音声と部屋データは削除しない。設定は保持し、indexを最後に切り替える。
通常ローカル12081、VPS、公開セルフホストZIP、Git pushはこの作業では変更しない。VPSのNative互換更新は以前のGo待ちのまま。本修正をVPSへ含める場合は、既存のstatic-only候補と違ってバックエンドの変更/再起動/依存更新も含むため、新しい候補を作って別途判断する。
